# Physical AI Agent System — 설계 개요

로봇 팔 원격시연(teleoperation)으로 모은 데이터가 클라우드를 돌아 학습·평가를 거쳐
다시 로봇으로 돌아오는 **한 바퀴**를 만드는 시스템. 그 설계와 구현 경험을 정리한 문서입니다.

> **이 레포에는 소스 코드가 없습니다.**
> 실제 구현은 회사 내부 비공개 레포에 있고, 여기에는 제가 직접 작성한
> 아키텍처 설명·기술 선택 근거·담당 범위만 담았습니다.
> 내부 설계 문서 원문, 스키마, 인프라 상세, 사내 식별자는 포함하지 않았습니다.

## 무엇을 푸는 시스템인가

VLA(Vision-Language-Action) 모델을 로봇 팔에 태우려면 **사람이 직접 팔을 잡고 시연한 데이터**가
필요합니다. 문제는 이 수집이 클라우드로 옮겨지지 않는다는 점입니다.

| 제약 | 왜 못 옮기나 |
|---|---|
| 원격시연 | 사람이 leader 팔을 물리적으로 잡는 것이 본질 — 헤드리스화 불가 |
| 로봇·카메라 | USB 직결. 클라우드가 디바이스를 소유할 수 없다 |
| 영상 인코딩 | 로봇 PC의 GPU 하드웨어 인코더에 종속 |
| 실시간 추론 | 30fps 제어 루프 — WAN 왕복이 들어갈 자리가 없다 |
| 네트워크 | 로봇 PC가 NAT·방화벽 안쪽 — 클라우드가 inbound를 열 수 없다 |

그래서 "수집을 클라우드로 옮긴다"가 아니라 **"엣지의 수집을 웹에서 지시하고, 결과를 표준 형식으로
저장·검증한다"** 로 문제를 다시 정의했습니다.

## 접근

- **지시는 클라우드, 실행은 엣지, 판정은 다시 클라우드.** 엣지가 아웃바운드로 지시를 당겨오므로
  방화벽에 구멍을 뚫지 않습니다.
- **데이터는 서버를 거치지 않습니다.** 엣지가 presigned URL로 오브젝트 스토리지에 직접 올려
  API 서버 대역폭 소모가 0입니다. 엣지는 스토리지 자격증명을 갖지 않습니다.
- **등록은 원자적입니다.** 업로드가 끝나면 무결성 게이트를 통과해야만 데이터셋으로 등재됩니다.
  부분 업로드가 유효한 데이터셋처럼 보이는 상황을 구조적으로 막았습니다.
- **끊겨도 수집은 계속됩니다.** 엣지 로컬 큐에 쌓아 두고 복구되면 자동 배출합니다.
- **평가 결과가 다음 수집의 방향이 됩니다.** 실패 모드를 식별해 같은 과제에 보강 수집을
  거는 루프를 데이터 모델에 넣었습니다.

## 결과

- 모노레포 **16개 서비스**를 역할 기준으로 나누되, 실제 배포는 **4개 단위**로 묶었습니다.
  디렉터리 수만큼 배포물을 만들지 않는다는 원칙을 세우고 문서로 고정했습니다.
- 수집 → 업로드 → 검증 → 등재 경로와 엣지 대시보드, 운영 뷰, 평가 서비스를 구현해
  컨테이너로 배포했습니다.
- 설계 결정을 **국문·영문 이중 언어 문서**로 관리하고, 결정 문서와 색인 문서를 분리해
  색인이 원본과 어긋나지 않도록 갱신 규칙을 정했습니다.
